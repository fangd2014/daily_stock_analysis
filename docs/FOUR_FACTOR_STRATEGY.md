# TickDB 四因子时点选股策略

## 目标与边界

本策略面向 100 万元模拟盘，跨全 A 股寻找最多 5 只股票，不限制科技板块，也不排除 `688008.SH`。
目标是用可复核的时点数据形成候选和交易门槛，而不是承诺固定收益。默认总仓位 60%，单股不超过
12%，行业最多 2 只；合格股票不足时持有现金。

TickDB 提供日线、最新行情、当日分时、市场指标和资金流。TickDB 当前不提供 A 股订单簿/逐笔成交，
也不提供新闻，因此新闻语义和 9:15—9:25 集合竞价快照必须来自独立的时点数据源。普通 9:30
分钟 K 线不能替代竞价未匹配买卖盘，也不能用于估算撤单率。

## 四个因子

### 1. 指数动量

对股票所属行业指数计算 5、20、60 日收益、20/60 日波动率、相对沪深 300 的 20 日超额收益和行业
成分股 20 日上涨广度。原始分数为：

```text
M = 0.25 * R5 / Vol20
  + 0.30 * R20 / Vol60
  + 0.20 * R60 / (sqrt(3) * Vol60)
  + 0.15 * (R20 - beta * BenchmarkR20)
  + 0.10 * (2 * Breadth20 - 1)
```

最后对全部行业指数做横截面百分位排名。只读取 `as_of` 之前已经完成的日 K 线，门槛为 60% 分位。

### 2. 舆情语义

每条新闻必须在采集时固化发布时间、正文哈希、正面/负面概率、相关性、来源可信度和新颖度。单条
权重为：

```text
weight = relevance * credibility * novelty * exp(-ln(2) * age_hours / 24)
polarity = (p_positive - p_negative) * weight
```

因子组合最近 24 小时加权极性、相对过去 20 个有新闻日期的情绪突变和新闻数量冲击，并单独保留重大
负面风险。相同股票与正文哈希只保留发布时间最近的一条；发布时间晚于截止点的事件会被剔除。

### 3. 区间学习与特征归因

模型不直接预测单一点位，而是用三套梯度提升分位回归分别预测未来 5 日超额收益的 q10、q50、q90。
训练样本必须同时满足 `feature_time <= cutoff` 和 `label_end <= cutoff`，避免标签穿越。模型边际为：

```text
expected_edge = q50 - transaction_cost
interval_score = expected_edge / max(q90 - q10, epsilon)
```

特征归因采用中位数遮挡：依次把当前样本的一个特征替换为训练集的中位数，原预测与遮挡后预测之差
就是该特征对 q50 的局部贡献。默认特征包括动量、相对强弱、波动率、换手异常、主力净流入和语义
情绪。买入门槛为预期边际大于 1%、q10 高于 -5%、归因置信度不低于 35%。

### 4. 竞价异动联动

使用 9:15—9:25 多个真实快照计算最终竞价跳空、匹配量相对历史中位数的量比、未匹配买卖盘失衡、
9:20 前买盘峰值相对 9:25 的衰减风险、行业竞价上涨广度以及与前夜舆情方向的一致性。全部买入门槛：

- 最终快照时间不早于 9:25；
- 跳空处于 0%—3%；
- 竞价量比不低于 1.5；
- 同行业竞价上涨广度不低于 60%；
- 未匹配买盘大于未匹配卖盘。

缺少真实竞价快照时，系统只输出晚间观察名单，`auto_buy_ready` 固定为 `false`。

## 两阶段选股与风控

晚上按指数动量 30%、舆情语义 30%、区间学习 40% 生成最多 20 只观察名单。次日 9:25 加入竞价
联动后，按 25%、20%、35%、20% 重新排名，依次选择最多 5 只，每行业最多 2 只。默认周频调仓、
最长持有 5 个交易日；单股亏损 5% 止损，盈利 8% 和 15% 分两档止盈，组合从高点回撤 12% 后停止
新增仓位。所有信号只用于模拟盘。

## 安装与运行

TickDB Skill 安装命令：

```bash
npx clawhub@latest install tickdb-market-data
```

正式全市场任务必须在项目 `.env` 配置 `TICKDB_API_KEY`，舆情语义计算必须在同一文件配置
`DEEPSEEK_API_KEY`。量化任务不从进程环境变量、`~/.zshrc` 或其他Shell配置读取这两个密钥，也不会
把Key写入缓存。未配置正式TickDB Key时，只允许TickDB官方试用名单，不会把试用名单冒充全市场股票池。

```bash
# 拉取并固化 TickDB 时点快照
python -m src.quant.tickdb_factor_snapshot \
  --symbols 600519.SH,601318.SH \
  --root data/quant_factor_snapshots/tickdb

# 计算四因子并生成观察名单/模拟买入报告
python -m src.quant.four_factor_runner \
  --config configs/quant/four_factor_strategy.json \
  --input-dir data/quant_four_factor/input \
  --output-dir reports/quant/four_factor \
  --as-of 2026-07-24T20:00:00
```

流水线输入支持同名 CSV 或 Parquet：`stocks`、`index_bars`、`member_bars`、`sentiment_events`、
`interval_training`、`current_features`，以及可选且必须成对出现的 `auction_snapshots`、
`auction_history`。输出包含每个因子明细、晚间观察名单、竞价因子、最终选择 JSON 和 Markdown 报告。

## 回测约束

四因子历史回测只有在历史新闻正文/采集时点和历史竞价快照均完整时才成立。用今天抓取的新闻评价
过去，或用普通分钟线补竞价盘口，都会产生幸存者偏差或未来数据泄漏。当前实现优先用于前瞻模拟盘：
每天固定保存数据快照、次日延迟成交、计入费用，并在积累足够样本后做滚动样本外检验。收益和最大
回撤必须由独立权益曲线重算，未通过目标时保留失败结论。
